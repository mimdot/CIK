ADDENDUM — FRESHNESS FALLBACK WHEN NO DEADLINE IS GIVEN
Some real, still-open positions never state a deadline — but I must NOT get posts
that are 1–2 years old. Add a freshness layer so undated ≠ kept forever:

  - For every record, derive an effective date in this priority:
      (1) deadline / validThrough (if parseable) — a future deadline always keeps
          the post, even if it was posted long ago (rare, but valid).
      (2) else posted_date / datePosted from the source or JSON-LD.
      (3) else a "last-seen/first-seen" date the script records the first time it
          encounters that URL — persist this in a small local state file (e.g.
          .seen_positions.json keyed by normalized URL) so an undated post gets a
          real timestamp from the run that discovered it, and ages naturally on
          later runs.
      (4) else, as a weak last resort, try to read a posted/updated date from the
          page itself (JSON-LD dateModified, <meta> article:published_time, or a
          visible "Posted on…" line) before giving up.

  - Add config MAX_AGE_DAYS (default 365). Drop a post when it has NO future
    deadline AND its effective date is older than MAX_AGE_DAYS. Keep it when the
    deadline is in the future, or the effective date is within the window.

  - Make the policy explicit and tunable, not silent:
      * KEEP_UNDATED_WITHIN_WINDOW = True  (undated but recently-seen → keep)
      * A truly dateless post with no seen-history: keep on FIRST discovery (so I
        don't miss a fresh listing), then let the seen-date age it out on later
        runs.
      * Log a per-run breakdown: how many kept by future deadline, by recent
        posted_date, by first-seen, and how many DROPPED as stale — so I can see
        why anything was excluded.

  - Flag each record with a freshness field (e.g. "deadline" / "posted" /
    "first_seen" / "undated_new") and a computed effective_date + age_days in the
    output, and surface it in the HTML dashboard so I can sort/filter by freshness.

  VERIFY: add self-tests — a post dated 18 months ago with no deadline is DROPPED;
  the same post with a future deadline is KEPT; an undated post is KEPT on first
  run and then DROPPED on a simulated run 400+ days later; a post from this month
  is KEPT.
